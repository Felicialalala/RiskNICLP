## A. 时间滑窗 ➜ 动态异质图

**关键问题：**
- 窗长 & 步长如何选？
- 流量跨窗延迟如何处理？

**完整回答与实现计划：**

### 1. 数据特征关键发现

基于5G-NIDD数据集的实际分析（1,215,890条流记录）：

| 流时长分布 | 记录数 | 占比 | 影响 |
|------------|--------|------|------|
| **≤4.5s短流** | 4,918 | 0.4% | 适合Slicing处理，边数膨胀影响极小 |
| **>4.5s长流** | 1,210,972 | 99.6% | 需要Carry-over处理，避免计算爆炸 |

**关键洞察**：数据呈现极度倾斜的时长分布，绝大多数攻击都是持续性的，这验证了粗粒度窗和长流处理策略的重要性。

### 2. 动态双尺度时间窗设计

#### 细粒度窗（固定）
- **配置**：3s窗/1s步
- **目标**：捕获攻击爆发转折点，驱动实时告警
- **适用**：所有攻击类型的瞬时特征

#### 粗粒度窗（动态自适应）
- **动态策略**：
  - 监控近3分钟内平均Dur
  - 若平均Dur > 10s → 30s窗/10s步
  - 否则 → 15s窗/5s步
- **目标**：汇聚慢热攻击，平滑评估指标
- **适用**：SlowrateDoS(73K)、长时扫描、持续性攻击

### 3. 混合跨窗流量处理策略

基于数据特征的精确分流：

#### 策略A: Slicing复制（短流专用）
- **适用条件**：`Dur ≤ 1.5 × 细窗 = 4.5s`
- **处理流量**：仅0.4%的短流，边数膨胀可控
- **实施要点**：
  - 将`[StartTime, LastTime]`分割到所有重叠窗口
  - 标记`ongoing=True`属性
  - 保持原始流量特征完整性

#### 策略B: Carry-over State（长流主力）
- **适用条件**：`Dur > 4.5s`
- **处理流量**：99.6%的长流，大幅降低计算复杂度
- **实施要点**：
  - 在DGL动态图中维护节点/边状态记忆
  - 新窗口仅更新增量变化
  - 利用时序GNN的内置记忆机制

### 4. Late-Fusion架构设计

```
数据流 → 双路并行处理 → 特征融合 → 预测

细粒度分支: 3s窗/1s步 → GNN_fine → H_fine (64维)
                                    ↓
粗粒度分支: 动态窗/动态步 → GNN_coarse → H_coarse (64维)
                                    ↓
融合层: concat(H_fine, H_coarse) → MLP → 链路预测 (128维)
```

**优势**：
- 实现量最小，便于benchmark对比
- 两分支可独立调试和消融实验
- 支持不同时间尺度特征的互补

### 6. 关键技术实现

**动态窗口监控**：
```python
class DynamicWindowManager:
    def __init__(self, monitor_window=180):  # 3分钟
        self.monitor_window = monitor_window
        self.dur_history = deque(maxlen=1000)
    
    def update_window_size(self, current_dur):
        self.dur_history.append(current_dur)
        avg_dur = np.mean(list(self.dur_history))
        
        if avg_dur > 10:
            return {"window_size": 30, "step_size": 10}
        else:
            return {"window_size": 15, "step_size": 5}
```

**混合跨窗处理**：
```python
def process_cross_window_flow(flow_record):
    dur = flow_record['Dur']
    
    if dur <= 4.5:  # 0.4%的短流
        return slicing_strategy(flow_record)
    else:  # 99.6%的长流
        return carry_over_strategy(flow_record)
```

**Late-Fusion特征融合**：
```python
class LateFusionModel(nn.Module):
    def __init__(self):
        self.fine_gnn = GraphSAGE(input_dim=112, hidden_dim=64)
        self.coarse_gnn = GraphSAGE(input_dim=112, hidden_dim=64)
        self.fusion_mlp = MLP(input_dim=128, output_dim=1)
    
    def forward(self, fine_graph, coarse_graph):
        h_fine = self.fine_gnn(fine_graph)
        h_coarse = self.coarse_gnn(coarse_graph)
        h_fused = torch.cat([h_fine, h_coarse], dim=-1)
        return self.fusion_mlp(h_fused)
```

## B. UE / gNB / Flow / Alert 节点识别

**关键问题：**
- 仅有 IP 对能否还原 5G 语义？
- 如何区分同 UE 多 QoS 流？

**我的分析：**
从数据分析中观察到IP地址模式（如10.155.15.x、10.50.150.x），这些应该是实验网内部地址。基于现有字段的启发式规则设计：
- `sTos`和`dTos`字段包含QoS标记（如cs0、ef、af11），可作为QoS流区分依据
- `Proto`字段包含sctp、udp等协议信息，有助于识别控制面/用户面
- 缺乏明确的IMSI或TEID字段，需要通过IP+端口+QoS的组合来推断UE实体

这种启发式映射虽然不完美，但足以构建异质图的基础结构。

## D. Risk-aware PPR 计算

**关键问题：**
- α 与惩罚因子选取？

**我的分析：**
PPR的α参数控制随机游走的重启概率。对于威胁传播建模，α=0.15是合理起点，因为：
- 保持与经典PPR文献的兼容性
- 允许威胁在图中有一定传播深度
- 避免过度集中在初始高风险节点

可考虑自适应α策略：对高风险节点使用较低α（如0.1）以增强传播，对普通节点使用标准α（0.15）。

**我的分析：**
