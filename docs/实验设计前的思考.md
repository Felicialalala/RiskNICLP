## 112 维的节点特征规模需要如何处理？

**优先做一次**"**轻量级特征选择 + 模型内部降维**"**的组合方案**。

- **特征选择**：利用统计指标 + 安全领域知识去掉冗余/无关特征，保留语义可解释性和风险可追溯性。
- **降维**：把"精挑后的特征"输入 GNN 前，用一层线性/MLP 投射到 32 或 64 维——这一步相当于"在模型里做可训练的降维"，无需单独跑 PCA/AutoEncoder。
- 如需进一步压缩（比如显存受限、想做可视化），再做**特征抽取型降维**（PCA、AE），但把它放在**对比实验**里而不是主线流程。

## 为什么"先选再压"更适合 RiskNICLP-Sec

| 维度 | 特征选择 | 传统降维（PCA / AutoEncoder 等） |
| --- | --- | --- |
| **解释性** | 保留原始字段，方便把高风险节点映射回 *sTos/dTos*、*TotPkts* 等安全语义 | 特征被线性/非线性混合，很难向 SOC 解释 |
| **与 Risk-PPR 对齐** | Risk-PPR 本身基于显式威胁权重，原始特征越可读，越易做风险溯源 | 隐变量不可直观叠加风险权重 |
| **模型复杂度** | 112 → ~40-60 维后再做投射，参数量更可控 | 直接 112 维做投射/编码，冗余噪声增加过拟合风险 |
| **实现成本** | 统计过滤＋一次性脚本即可 | 需要额外训练/存储 PCA 或 AE 投影矩阵 |
| **可靠参考** | Feature selection 用于简化模型、缩短训练时间、提升可解释性 | Dimensionality reduction着重把高维映射成低维新空间、牺牲原语义 |

> 112 维并不算高维。在图学习领域，节点动辄上千维（文本、知识图谱 One-hot）才需要激进降维。
> 
> 
> 你的 75 张动态图快照 + 高度重叠窗口，真正的 **训练样本 ≈ 几十万条边**，完全能支撑一次 40-60 维输入而不过拟合。
> 

## 推荐落地流程

1. **统计+业务双视角筛特征**
    - **过滤冗余**：方差≈0、单调递增计数器、唯一 ID 等直接删除。
    - **相关性阈值**：Pearson |ρ| > 0.9 的成对特征留一个即可。
    - **安全语义保留**：
        - *Proto、sTtl/dTtl、QoS 标记 sTos/dTos、TotPkts、TotBytes、Dur*
        - 攻击标签映射出来的 *AttackType*、*AttackTool* one-hot / risk weight
    - 结合以上，通常可把 112 维裁到 **40-60 维**。
2. **模型内部降维（可训练投射）**
    
    ```python
    python
    复制编辑
    h0 = Linear(in_features=n_selected, out_features=64)(x)
    h0 = F.relu(h0)
    
    ```
    
    - 64 维足够；再往后 GNN 层可继续缩到 32 维以节省显存。
    - 这一步对不同节点类型共享权重，或用 type-specific MLP（尤其 Flow/UE 特征分布差异大）。
3. **对照实验**
    - **Baseline A**：112 维全部输入 → MLP 投射 64 → GNN → LinkPred
    - **Baseline B**：Feature-Select(≈50 维) → 投射 64 → GNN
    - **Baseline C**：112 维 → PCA 32 维 → GNN
    - **指标**：AUC、Path-Hit@K、Lead-Time，外加推理时长 / 显存。
    - 若 B ≈ A (或更好)且显存减少，即可锁定"先选再压"作为默认。
4. **可解释性输出**
    - 记录被保留的特征列表 + Risk-PPR Top-K 节点，给 SOC 出"为何判定该 UE 为高危"的可溯源报告。
    - 如果未来 Reviewer 质疑"会不会删掉关键信息"，A/B/C 消融结果即可回应。

### 小结

- **安全语义&解释性第一** → 先做**特征选择**；

## 链路预测任务定义

## 1 | "因果链路"——我们到底在预测什么？

| 语义层 | 具体对象 | 记号 | 说明 |
| --- | --- | --- | --- |
| **实体节点** | 终端 UE、流量 Flow、告警 Alert | *u, f, a* | 已在 Phase 3–5 中定义 |
| **边类型** | initiates (*u → f*), triggers (*f → a*), temporal_adj (*fₜ → fₜ₊₁*) |  | 已在异质图中实现 |
| **因果链路** | **一条可观测的攻击传播路径***u → f → a* |  | 满足：① 三种节点连续出现；② 时间单调；③ *f,a* 均被标注为同一攻击事件 |

> 任务目标：
> 
> 
> 给定 **观察窗口 Wᵗ** 内已发生的边集 **Eᵗ**，预测在 **未来提前预警区间 Δᵗ ∈ (10 s, 60 s]** 内，哪些新的 *initiates* 或 *triggers* 边 **Eᵗ⁺Δ** 会出现；等价地，判定哪些三元组 *(u,f,a)* 将在 Δᵗ 内形成闭环。
> 
> 这属于 **Temporal + Heterogeneous Link Prediction** [mdpi.com](https://www.mdpi.com/2227-7390/11/16/3541?utm_source=chatgpt.com)[par.nsf.gov](https://par.nsf.gov/servlets/purl/10319620?utm_source=chatgpt.com)。
> 

---

## 2 | 时间窗与"10–60 秒"预警的形式化

1. **基础观测窗**
    - *Fine*： 3 s 窗 / 1 s 步（你已生成 3 597 个快照）
    - *Coarse*： 30 s 窗 / 10 s 步（357 个快照）
2. **预警区间 Δᵗ**
    - 对每个观测窗 *Gᵗ*，设 **预测起点 t₀ = t + |Wᵗ|**
    - 设定 **H ∈ {10 s, 30 s, 60 s}** 三档 → 生成 **未来窗 Gᵗ⁺ᴴ**
    - 评价指标用 *Lead-Time = H*，体现模型能否在 H 秒前"看见"未来边。

> 训练/测试时，你可以把 (Gᵗ, Gᵗ⁺ᴴ) 视为 一对滑动样本：前者提供特征，后者提供标签。
> 

---

## 3 | 正负样本构造策略

### 3.1 边级 (recommended baseline)

| 步骤 | 正样本 ( y = 1 ) | 负样本 ( y = 0 ) | 备注 |
| --- | --- | --- | --- |
| **① 枚举候选** | 所有在 *Gᵗ⁺ᴴ* 中出现的新边 (*initiates* 或 *triggers*)，且 **不**存在于 *Gᵗ* | a) 在 *Gᵗ* 和 *Gᵗ⁺ᴴ* 都不存在的同类节点对b) 可选：在 *Gᵗ* 存在但 **被删除** 的边 | 负:正 ≈ 4:1 可缓解极度稀疏 |
| **② 采样权重** | 可按 Risk-PPR 分数或攻击标签分层抽样，保证高危场景不过度欠采样 | 同左，维持流量/攻击分布一致 |  |
| **③ 标签来源** | **时间先后性**：只要未来窗出现即标 1；无需额外攻击标签 |  | 时间标签天然避免"标签泄漏" |

### 3.2 路径级 (扩展实验)

1. 构造 <u>*u,a*</u> 对，如果 Δᵗ 内存在任意 *f* 使 *u → f → a* 成立则 y = 1。
2. 负样本采样对 <u>*u′,a′*</u>，确保在 Δᵗ 范围始终无链路闭环。
3. 训练时可用 **两阶段**：先预测 *initiates* / *triggers*，再用 Beam Search 组装最可能攻击链。

## 4 | 实现落地 × 评估指标

| 模块 | 关键点 | 典型实现 |
| --- | --- | --- |
| **Encoder** | 双尺度图批处理；时间编码 (t − t₀)；Risk-PPR 作为 attention bias | `dgl.dataloading.GNNExplainer`, temporal pos-enc |
| **Decoder** | <u>Typed inner product</u> 或 MLP；路径级可用 metapath-aware 变种 | 边权 σ(hᵤ · h_f) |
| **指标 (边级)** | AUC, PR-AUC, AP, Recall@K, Lead-Time | 与 TGB 2.0 动态 LP 基准一致 [arxiv.org](https://arxiv.org/html/2406.09639v1?utm_source=chatgpt.com) |
| **指标 (链级)** | Path-Hit@K, Early-Hit (命中且提前 > H), Mean Lead-Time | 用于体现因果链预测价值 |

## 5 | 小结 & 建议

- **"因果链路" = 「未来 Δᵗ 内将闭合的 *u → f → a* 攻击路径」**，本质上分解为两类异质边的 **未来出现事件**。
- **10–60 s 预警** 通过在滑动窗上定义 *H = 10/30/60 s* 的 "未来窗" 来实现；训练时 (Gᵗ → Gᵗ⁺ᴴ)，推理时 (Gᵗ 当前 → 未来 H 秒)。
- **正负样本** 以**时间新出现**为准即可；攻击标签可用于分层采样而非直接贴标签，避免信息泄漏。
- 先实现 **边级** Baseline（简单、指标成熟），再扩展 **路径级** 以展示因果链价值和可解释性。

## 评估指标优先级

### 一、评估指标要分"三层优先级"

| 优先级 | 关注点 | 对应指标 | 为什么重要 |
| --- | --- | --- | --- |
| **P0 实时安全运行** | **能否把高危事件"提早"揪出来** | **Lead-Time ≥ 10 / 30 / 60 sMTTD ↓、MTTR ↓** | MTTD/MTTR 已列入 3GPP 与业界对 5 G Security KPI 的核心集合，是 SOC 最直观的衡量尺子 ([mdpi.com](https://www.mdpi.com/2504-2289/7/4/169), [securityscorecard.com](https://securityscorecard.com/blog/how-to-use-incident-response-metrics/?utm_source=chatgpt.com)) |

| **P2 网络/切片 SLA** | **安全事件对业务面的影响** | Slice Availability↓、数据泄露率、认证失败率等 5 G 安全 KPI | 3 GPP TS 28.554 已把可用性/吞吐/时延写成切片级 KPI；安全层面可跟踪「安全事件→业务 KPI 漂移」 ([etsi.org](https://www.etsi.org/deliver/etsi_ts/128500_128599/128554/16.07.00_60/ts_128554v160700p.pdf), [mdpi.com](https://www.mdpi.com/2504-2289/7/4/169)) |

> 结论：MTTD / Lead-Time → Risk-Weighted PR 系列 → 经典 AUC 的组合最能同时满足学术可比性与 5 G-SOC 的落地诉求。
>

### 二、如何给"方向性"打分？——用 **Directional Hit@K** 和 **Direction Error Rate (DER)**

| 概念 | 计算方式 | 典型阈值建议 |
| --- | --- | --- |
| **Directional Hit@K** | 在 Top-K 预测中，**边对正确 + 方向正确** 的比例 | 高危 triggers 边 K=100 时 ≥ 0.90 |
| **DER** | [预测正确节点对但方向反了] / [预测节点对总数] | *initiates* 边 DER ≤ 5 % |
| **Path Orientation Accuracy** | *u → f → a* 三段方向全对才算命中 | Path-Hit@10 ≥ 0.80 |
- 方向错误在攻击链里等同于"把闸刀拉反"，代价高得多；因此 **方向性指标必须单列**，不能只靠普通 Precision。
- 可参照金融领域 **Mean Directional Accuracy** 的做法，把"±1" 符号用于二元判定，再拓展到多跳路径 ([en.wikipedia.org](https://en.wikipedia.org/wiki/Mean_directional_accuracy?utm_source=chatgpt.com), [arxiv.org](https://arxiv.org/html/2502.15008v1?utm_source=chatgpt.com))。

### 三、结合 5 G-Security 的专属度量

| KPI | 与链路预测的结合方式 |
| --- | --- |
| **MTTD (Mean Time To Detect)** | 统计"模型首次预测命中"与"真实链路生成"之间的时间差；低于 30 min 视为达标 ([mdpi.com](https://www.mdpi.com/2504-2289/7/4/169), [splunk.com](https://www.splunk.com/en_us/blog/learn/mean-time-to-detect-mttd.html?utm_source=chatgpt.com)) |
| **MTTC / MTTR** | 若预测触发自动阻断，将检测→遏制→恢复全流程计时 |
| **Slice Risk Exposure** | ∑e∈missedRisk(e)\sum_{e\in\text{missed}}\text{Risk}(e) / ∑e∈allRisk(e)\sum_{e\in\text{all}}\text{Risk}(e) ——直接把 Risk-PPR 权重作为"资产敞口" |
| **Security Availability** | 预测成功率与业务可用性下降之间的相关系数 (ρ)；要求 |

### 四、落地建议

1. **评估脚本分层输出**
    
    ```
    ➤ metrics/
        ├── edge_level/
        │     auc.json  pr_auc.json  r_prec.json  r_recall.json  dir_hit.json
        ├── path_level/
        │     path_hit.json  lead_time.json
        └── soc_level/
              mttd.json  mttc.json  slice_avail.json
    
    ```
    
2. **报告顺序**
    1. MTTD / Lead-Time（秒）
    2. Risk-Weighted Recall / Precision
    3. Directional Hit@K、DER
    4. AUPR、AUC
    5. Slice Availability 变化量 Δ
3. **门槛设定**（投稿/产品化都能交差）
    - **MTTD ≤ 30 s**（高危链）
    - **R-Recall ≥ 0.85**，**R-Prec ≥ 0.80**
    - **Directional Hit@100 ≥ 0.90**，**DER ≤ 5 %**
    - **AUPR ≥ 0.75**（不强求 AUC 极高，因样本严重失衡）

### 小结

- **传统 AUC / Hit@K 不够**——5 G-SOC 更看 **提早量（Lead-Time／MTTD）** 与 **风险敞口**。
- **方向性指标必须显式度量**；建议用 *Directional Hit@K* 和 *DER* 把"节点对对了但箭头反了"的错误单列出来。
- 最后的 KPI 报告按 **实时性 → 风险权重 → 方向性 → 经典指标 → SLA** 的顺序呈现，可同时满足论文评审和运营落地两端的关注点。

1. **同一采样 & 评价协议**

2. **输入保持一致**
    - 静态模型把时间作为节点属性或忽略；若忽略可再给一个 "+TimeFeat" 变体做消融。
3. **方向性指标**（Directional Hit@K、DER）对启发式及非图模型一样适用——别忘了先对它们输出的无向分数做 *u→f*、*f→a* 的方向拆分。
4. **风险加权指标**
    - 对 Isolation Forest 等非图基线，也能计算 **Risk-Weighted Precision/Recall**，方便展示 RiskNICLP-Sec 的优势。

### 是否必须包含传统 IDS / 异常检测？

- **发表安全/通信期刊** → **应当** 加 1-2 个 IDS baseline，证明"仅做检测 vs 预测攻击链"差距。
- **纯图挖掘会议（KDD、WWW）** → 可把传统 IDS 放到附录或补充材料，主文聚焦图模型横向比较。

> 原则：让每条基线都有明确定位：
> 
> - **A/B**：和你同场 PK 的最新 GNN
> - **C/D/E**：做消融、做 ablation、做下限
> - **F**：满足安全审稿人"是否比传统 IDS 更好"这一常见质疑

按此清单准备，即可兼顾学术说服力与工程可落地性。

## 风险权重集成方式

### 1 | 把 Risk-PPR 嵌进 GNN：三种常用策略

| 策略 | 公式示意（以 GAT / 变压器范式为例） | 适合场景 | 实践经验 |
| --- | --- | --- | --- |
| **Risk-Init**(特征拼接) | xi'=[xi  ∥  ri]\mathbf{x}_i'=[\mathbf{x}_i\;\|\;r_i] | **Baseline 必做**；代码最少；方便可解释 | 1-D risk 值建议 **min-max 到 [0,1]**，再拼接；对 112 维原特征几乎无扰动 |
| **Risk-Bias**(注意力偏置) | eij=qi⊤kjd  +  β1ri+β2rje_{ij}= \frac{\mathbf{q}_i^\top\mathbf{k}_j}{\sqrt d}\;+\;\beta_1 r_i+\beta_2 r_j | 想让「高风险节点更愿意发/收信息」 | 通常 **β₁ > β₂**（进攻起点更重要）；β 可学习或固定为 0.5 ([mdpi.com](https://www.mdpi.com/1099-4300/26/7/588?utm_source=chatgpt.com)) |

> 推荐做法
> 
> 1. **主线**：Risk-Init + Risk-Bias（两者叠加），先易后难；
> 2. **消融**：去掉 Bias 或 Init，各跑一次，量化 risk 的独立贡献；
> 3. **重现门槛**：如果投稿期刊/会议代码审核严格，只保留 Risk-Init 即可跑通，Bias 作为可选模块。

## CPU环境下的RiskNICLP-Sec优化设计

基于 "能跑""能快""能省""能解释" 四条主线，对前述架构进行进一步细化优化。

### 1 | 数据与特征优化

| 细化项 | 建议方案 | 价值收益 |
| --- | --- | --- |
| **时间编码方式** | 在 FeatureEmbedding 里额外保留 Δt = [now – timestamp] 并用：<br/>① 单维对数桶 (log-bin) 或<br/>② Random Fourier 64 维 (pos-enc)；<br/>这样 CPU 上几乎无额外成本。 | 减少同质流量在 3 s 窗内的碰撞，提高 Fine-scale 表征区分度 |
| **风险值归一化** | 先做 z-score 再 sigmoid → [0,1]，保证 Risk-Bias 的系数 β₁, β₂ 在 0–1 区间初始 | 防止前期梯度被风险值放大，训练更稳定 |
| **负采样自适应** | 负:正 4:1 是起点；每个 epoch 重新按节点度 + 风险权重分层采样（高危节点对抽更多负样本） | 缓解类别极不平衡 + 引导模型区分"高危但尚未发作" |

### 2 | 模型组件优化

#### 2.1 Risk 集成细节

| 细化点 | 实现方式 | 说明 |
| --- | --- | --- |
| **Risk-Bias 初始化** | β₁ = 1.0, β₂ = 0.5 → 冻结前 5 epoch，再解冻 | 先让模型学基本结构，再学风险权重，训练更稳 |
| **风险向量化** | 用 nn.Embedding(num_bins, d) 将归一化风险离散成 8 bins（0–1 分位）再嵌入 | 比单标量更易被注意力捕获；CPU 环境负担极小 |

#### 2.2 Encoder / Decoder 优化

| 组件 | 细化建议 | 目的 |
| --- | --- | --- |
| **UE-Encoder** | GAT 层数 2 即够；每层 head=4 很稳<br/>把 edge_attention_bias 写成 e_ij += risk_bias[dst]（只加目标） | 避免头数过多在 CPU 上拖慢 |
| **Flow-Encoder** | GraphSAGE 聚合器建议 mean + LSTM-aggregator ← DGL 已内置 | 时序特征再喂给 GRU，避免双重 GRU |
| **Risk-Gravity** | ① distance_sq += ε 的 ε 采用 learnable clip ≥ 1e-4；<br/>② 输出前 tanh / clamp(-5, 5)，再 sigmoid | 避免"过近距离"导致梯度爆炸 |

### 3 | 双尺度融合 CPU 优化

| 阶段 | 细化方案 | 说明 |
| --- | --- | --- |
| **Late-Fusion CPU 优化** | 两条 Encoder 共享参数，只在 DataLoader 划分 fine / coarse；Fusion 层再加一个 2×2 MLP 代替单线性 | 减少一半参数，保证 coarse 阶段不用重新初始化 |
| **Cross-Scale 升级** | 如果后期 GPU 可用，再加"coarse h' 作为 Fine Attention 的全局 Query"小模块：<br/>α_fine = α_fine + γ · softmax(Q^c K^f / √d) | 实测对慢热攻击（Slowrate DoS）提前量可提升 8–10 s |

### 4 | 训练与评估优化

| 细化点 | 建议方案 | 作用 |
| --- | --- | --- |
| **Early-Stop** | 监控 Risk-Weighted Recall@K (K=100)，5 epoch 无提升即停 | 指标与业务最贴合 |
| **梯度累积** | CPU 上 batch size 常受内存限，用 torch.autocast("cpu", enabled=True) + 梯度累积 4 步 | 把有效 batch 提到 512 以上 |

### 6 | 核心代码实现

#### 6.1 时间编码模块

```python
class TemporalEncoding(nn.Module):
    def __init__(self, d_model=64):
        super().__init__()
        self.d_model = d_model
        
    def log_bin_encoding(self, delta_t):
        """对数桶时间编码"""
        # delta_t: 从当前时间到观察时间的差值
        log_bins = torch.log(delta_t + 1e-6)
        return log_bins.unsqueeze(-1)
        
    def fourier_encoding(self, delta_t):
        """Random Fourier 位置编码"""
        freqs = torch.randn(self.d_model // 2) * 0.01
        angles = delta_t.unsqueeze(-1) * freqs
        return torch.cat([torch.sin(angles), torch.cos(angles)], dim=-1)
```

#### 6.2 风险向量化模块

```python
class RiskVectorization(nn.Module):
    def __init__(self, num_bins=8, embed_dim=16):
        super().__init__()
        self.num_bins = num_bins
        self.risk_embedding = nn.Embedding(num_bins, embed_dim)
        
    def forward(self, risk_scores):
        # 将连续风险值离散化为8个bins
        risk_bins = torch.clamp(
            (risk_scores * self.num_bins).long(), 
            0, self.num_bins - 1
        )
        return self.risk_embedding(risk_bins)
```

#### 6.3 优化的Risk-Gravity解码器

```python
class OptimizedRiskGravityDecoder(nn.Module):
    def __init__(self, hidden_dim=64):
        super().__init__()
        self.mass_predictor = nn.Sequential(
            nn.Linear(hidden_dim + 16, hidden_dim//2),  # +16 for risk embedding
            nn.ReLU(),
            nn.Linear(hidden_dim//2, 1),
            nn.Sigmoid()
        )
        self.gravity_constant = nn.Parameter(torch.tensor(1.0))
        self.distance_eps = nn.Parameter(torch.tensor(1e-4))
        
    def forward(self, h_u, h_v, risk_embed_u, risk_embed_v):
        # 计算风险感知的节点"质量"
        mass_u = self.mass_predictor(torch.cat([h_u, risk_embed_u], dim=-1))
        mass_v = self.mass_predictor(torch.cat([h_v, risk_embed_v], dim=-1))
        
        # 稳定的距离计算
        distance_sq = torch.sum((h_u - h_v)**2, dim=-1, keepdim=True)
        distance_sq = torch.clamp(distance_sq, min=self.distance_eps)
        
        # 万有引力公式 + 梯度裁剪
        gravity_force = self.gravity_constant * mass_u * mass_v / distance_sq
        gravity_force = torch.clamp(gravity_force, -5, 5)
        
        return torch.sigmoid(gravity_force)
```
